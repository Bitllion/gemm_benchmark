## 项目概述

本项目是一个高性能 GEMM（通用矩阵乘法）基准测试实现，使用 CUDA 进行 GPU 加速计算。构建系统基于 GNU Make 构建，支持多种 GPU 架构和目标平台的灵活配置。

### 核心特性
- **多架构支持**：支持多种 NVIDIA GPU 架构（sm_35, sm_50, sm_60, sm_70, sm_80）
- **优化选项**：提供多种编译优化级别和调试模式
- **跨平台兼容**：支持 Linux、Windows 等主流操作系统
- **模块化设计**：易于扩展新的 GPU 架构和优化选项

## Makefile 配置详解

### 基础变量配置

Makefile 定义了构建系统的核心变量，包括编译器路径、目标架构和优化选项。

```makefile
# 编译器配置
NVCC = nvcc
CXX = g++

# 目标架构
ARCH_FLAGS = -arch=sm_70

# 优化级别
OPT_FLAGS = -O3

# 调试模式
DEBUG_FLAGS = -g -G
```

### 编译标志管理

系统提供了灵活的编译标志管理机制，支持不同构建目标的定制化配置。

#### 基础编译标志
- `-std=c++11`：启用 C++11 标准支持
- `-Xcompiler`：传递参数给宿主编译器
- `-Xptxas`：传递参数给 PTX 汇编器

#### 优化标志详解
- `-O3`：最高级别优化
- `-fast-math`：启用快速数学运算
- `-use_fast_math`：使用快速数学函数

## CUDA 编译选项定制

### 优化级别配置

系统支持多个级别的优化配置，用户可以根据需求选择合适的优化策略。

#### 开发模式
```bash
make debug ARCH_FLAGS="-arch=sm_70" OPT_FLAGS="-O0 -g -G"
```

#### 发布模式
```bash
make release ARCH_FLAGS="-arch=sm_70" OPT_FLAGS="-O3 -Xptxas -dlcm=ca"
```

### 性能调优选项

#### 内存访问优化
- `-Xptxas -dlcm=ca`：强制使用缓存访问
- `-Xptxas -dlcg=1`：启用常量全局缓存
- `-Xptxas --fmad=false`：禁用 FMA 指令

#### 寄存器分配优化
- `-Xptxas -v`：显示寄存器使用情况
- `-Xptxas --maxrregcount=64`：限制最大寄存器数量

## 多目标平台构建配置

### 支持的 GPU 架构

系统预定义了多种 NVIDIA GPU 架构的支持：

| 架构标识 | GPU 系列 | 特性 |
|---------|----------|------|
| sm_35 | Kepler 系列 | 基础 CUDA 支持 |
| sm_50 | Maxwell 系列 | 改进的内存子系统 |
| sm_60 | Pascal 系列 | Tensor Core 支持 |
| sm_70 | Volta/Turing | 混合精度计算 |
| sm_80 | Ampere | 第三代 Tensor Core |

### 自定义架构配置

用户可以通过环境变量或命令行参数指定目标架构：

```bash
# 单架构构建
make ARCH_FLAGS="-arch=sm_80"

# 多架构构建
make ARCH_FLAGS="-arch=sm_70 -arch=sm_80"
```

### 交叉编译支持

系统支持在不同平台上为目标架构进行交叉编译：

```bash
# Linux 到 Windows
make HOST_OS=windows TARGET_ARCH=sm_70

# macOS 到 Linux
make HOST_OS=linux TARGET_ARCH=sm_80
```

## 依赖管理与版本兼容

### CUDA Toolkit 要求

系统对 CUDA Toolkit 版本有明确要求：

- **最低版本**：CUDA 11.0
- **推荐版本**：CUDA 11.8+
- **最新支持**：CUDA 12.x

### 编译器兼容性

#### GCC 版本要求
- **Linux**：GCC 7.0+
- **macOS**：Clang 10.0+
- **Windows**：MSVC 2019+

#### Python 工具链
- **Python 3.7+**：用于后处理和结果分析
- **NumPy**：数值计算库
- **Matplotlib**：图表生成

### 依赖检测机制

构建系统自动检测依赖项并报告缺失信息：

```bash
# 检查依赖
make check-deps

# 安装缺失依赖
make install-deps
```

## 构建脚本扩展与自动化

### 自定义构建目标

用户可以添加自定义构建目标来扩展功能：

```makefile
.PHONY: custom-build
custom-build:
	@echo "执行自定义构建..."
	nvcc $(NVCC_FLAGS) -o custom_target main.cu
```

### 批量构建脚本

创建批量构建脚本以支持多架构并行构建：

```bash
#!/bin/bash
# build_all.sh
for arch in sm_35 sm_50 sm_60 sm_70 sm_80; do
    make clean
    make ARCH_FLAGS="-arch=$arch" &
done
wait
```

### CI/CD 集成

#### GitHub Actions 示例

## 常见问题与解决方案

### 编译错误处理

#### CUDA 版本不匹配
**问题**：`nvcc fatal : Unsupported gpu architecture 'compute_XY'`
**解决**：检查 CUDA 版本支持的架构，更新 `ARCH_FLAGS` 变量

#### 链接错误
**问题**：`undefined reference to 'cublasSgemm'`
**解决**：确保正确链接 cuBLAS 库，检查 `LIBS` 变量配置

#### 内存不足
**问题**：`out of memory during compilation`
**解决**：减少优化级别或使用 `-Xptxas --disable-cache` 选项

### 运行时问题

#### GPU 驱动问题
**问题**：`CUDA driver version is insufficient for CUDA runtime version`
**解决**：更新 NVIDIA 驱动程序到最新版本

#### 性能问题
**问题**：程序运行缓慢
**解决**：启用适当的优化选项，检查内存带宽利用率

### 调试技巧

#### 启用详细日志
```bash
make VERBOSE=1
```

#### 生成调试符号
```bash
make DEBUG=1
```

#### 性能分析
```bash
make PROFILE=1
nsys profile ./gemm_benchmark
```

```cpp
cudaStreamCreate(&stream);
kernel<<<gridSize, blockSize, 0, stream>>>(...);
```
